KNOWN BUGS
==========

BUG #1 — dataSource routing (architectural flaw)
-------------------------------------------------
File: server/routes.ts, line 20

  const dataSource = isLocalMode ? storage : externalApi;

When DEV_MODE is not "LOCAL" (i.e. in production / normal dev), dataSource
points to externalApi instead of storage. externalApi.ts holds its own
separate, out-of-sync copy of all game data (gamesData array). This means:

  - Word validation goes through externalApi (O(n) array scan) instead of
    MySQLStorage's pre-loaded Set (O(1)).
  - Any improvements made to game-data.ts (new fields, new games, updated
    metadata) are silently ignored — externalApi.ts never picks them up.

Fix: change line 20 to:
  const dataSource = storage;

Both MySQLStorage and MemStorage implement the full IStorage interface and
read from game-data.ts, so all routes continue to work correctly.


BUG #2 — Ladder Rush leaderboard tabs missing (independent bug)
---------------------------------------------------------------
Files: server/game-data.ts, client/src/pages/leaderboard.tsx

Ladder Rush and Ladder Rush: Double Swap each have three scoring modes
(Easy/4L, Medium/5L, Hard/6L) defined in server/game-data.ts via the
`modes` array field. The leaderboard page renders sub-tabs for these modes
when selectedGameObj.modes is present (hasModes = true).

The tabs do NOT appear even when dataSource = storage (confirmed on local
machine with DEV_MODE="LOCAL"). Leaderboard entries exist in the DB with
the correct per-difficulty slugs (e.g. "ladder-rush-4", "ladder-rush-5",
"ladder-rush-6") — the data is there but unreachable through the UI.

Root cause NOT yet identified. Fixing Bug #1 does NOT resolve this.
Likely candidates to investigate:
  - The `modes` field is not making it from /api/games to the frontend
    (check what the API actually returns for ladder-rush at runtime)
  - The leaderboard page game selector uses slug "ladder-rush" but
    selectedGameObj lookup or hasModes check fails for some reason
  - The Game type serialisation drops the `modes` field somewhere

Fix: needs investigation before implementing.
