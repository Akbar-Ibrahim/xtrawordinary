xtraWordinary — Full Feature Reference
========================================
Last updated: April 2026

This document describes every feature currently in the app in detail,
followed by suggestions and nice-to-haves for each section.


========================================================================
1. GAME LIBRARY (24 games, 50+ slugs/modes)
========================================================================

The homepage shows all games as browsable cards. Each card shows the
game name, short description, difficulty badge, estimated time, and play
count. Clicking a card goes to the game-detail page.

--- WORD LADDER ---
Transform one word into another by changing exactly one letter at a time.
Each intermediate word must be a valid dictionary word. Features a "par"
system (target steps), a visual ladder showing the chain, hints, and a
scoring system based on how close to par the player finishes.

--- ANAGRAM SOLVER ---
Given a scrambled set of letters, find all valid anagram arrangements.
Multiple anagrams are possible per set. Seeded for challenges and daily.

--- WORD SCRAMBLE ---
A single scrambled word is shown. Players unscramble it. Words have
categories (e.g. animals, geography). Seeded for reproducible puzzles.

--- DEFINITION MATCH ---
A definition is shown; the player types the word it describes. Tests
vocabulary depth rather than spelling. Seeded for challenges and daily.

--- LETTER POOL ---
Two modes:
  With Pool: a set of letters is given; player spells valid words using
    only those letters. Longer words score more.
  Without Pool: free-form spelling with automatic submission. Order
    bonuses, hints, and a lives system.
Seeded for challenges and daily.

--- WORD MAKER ---
Given a base word, find as many derivatives as possible (prefixes,
suffixes, compound variations). Each base word has a known maximum.
Seeded for challenges and daily.

--- LENGTH CHALLENGE (word-length) ---
Players must find words of a specific length within a time limit.
Difficulty increases with target length. Seeded for challenges.

--- POSITION MASTER (letter-position) ---
Players identify which position a given letter appears in within a word.
Tests positional letter awareness. Seeded for challenges.

--- LETTER HUNT ---
Given a set of letters, players find as many words as possible that
contain all of those letters. Seeded for challenges.

--- WORD CHAIN ---
A word is given; the player must respond with a word beginning with the
last letter of the previous word (or last two letters in hard mode).
The computer plays back, and the player must keep the chain going.
Variations: first/last letter. Difficulty levels: easy/medium/hard.
Computer word selection is server-side (dictionary never exposed).

--- LETTER BALANCE ---
Players are shown a target ratio of vowels to consonants and must form
words matching that balance. Tests letter composition awareness.
Server-side config drives the ratios.

--- LETTER FREQUENCY ---
Players are given a frequency chart of letters in a hidden word and must
guess the word. Seeded for challenges and daily.

--- WORD STACK ---
Players are given a 2-letter starting word and must build up to a target
word by adding one valid word at a time (each longer than the last, each
a real word). Think of it as a one-directional Word Ladder.

--- NO REPEATS ---
Players type words but can never reuse a letter they've already used
across all submitted words in the session. Forces creative vocabulary
under constraint.

--- WORD SPLIT ---
A long target word is shown; players must split it into two or more
valid shorter words using all the letters. Tests compositional thinking.

--- PROGRESSIVE REVEAL ---
Letters of a hidden word are revealed one at a time. Players guess
as early as possible — earlier correct guesses score more points.
Each word has a subcategory hint.

--- WORD SWEEP (two modes, one game entry) ---
Classic: A 6×6 grid of letters with gravity and shuffle. Players swipe
  to find any valid words. Free-form; no target word list.
  Scoring: length-based.
Guided (Word Unpack): A 6×6 grid with a known target word list. Timed.
  Speed scoring: max(50, 1000 - elapsed_seconds×5 - wrong_attempts×50).
Both modes seeded. Daily challenge and group rounds use seed parity to
alternate modes (even seed → Classic, odd seed → Guided).
Separate leaderboard tabs for each mode.

--- WORD ROOTS ---
Given a canonical root word, find as many valid derivatives as possible
(e.g. "run" → running, runner, runoff). 5 roots per session. Seeded.

--- LADDER RUSH ---
A timed word ladder race. Unlike Word Ladder, there is no known target —
players chain as many valid one-letter-change words as possible before
time runs out. Three word lengths: 4, 5, or 6 letters.

--- LADDER RUSH: DOUBLE SWAP ---
Same as Ladder Rush but each step must change exactly two letters.
Significantly harder; same three word lengths.

--- SHELL WORDS (6 sub-modes) ---
Concept: removing the first and last letter of a word reveals a hidden
inner word (e.g. BRAND → RAN).
  Blitz Classic (90s): find any shell words; score = 10 + outerLen×2
  Blitz Survival: 8s per word; correct answer resets the clock
  Wrapper Classic (2min): given an inner word, find all wrappers;
    score = found×15 + timeLeft×2
  Wrapper Survival: 8s per wrapper; correct → new inner word
  Crack Classic (10 rounds): given boundary letters, type the middle;
    score = 20 + innerLen×8
  Crack Survival: 8s per boundary pair; correct → new pair
APIs: validate, puzzle (seed), crack (seed). Server-side only.

--- DEEP SHELL WORDS (6 sub-modes) ---
Same structure as Shell Words but removes the first TWO and last TWO
letters (e.g. STRANGER → RANG). Minimum outer word length: 7 letters.
Same 6 sub-mode layout as Shell Words.
APIs: validate, puzzle (seed), crack (seed). Server-side only.

--- WORD BLOOM (2 modes) ---
Given a seed word (2–4 letters), insert exactly one letter anywhere
(without rearranging) to grow it step by step into the longest chain.
Example: AM → AIM → AIMS → MAIMS.
  Classic (2min): grow the chain as deep as possible;
    scoring: 10 pts base + 5 pts × (current word length − seed length)
  Survival: 8s per step; any correct insertion resets clock
Precomputed insertion adjacency graph; memoized DFS for max depth.
APIs: puzzle (seed), validate (current + next).

--- WORD STRETCH (2 modes) ---
Given a seed word (3–6 letters), insert exactly one letter anywhere
to form a valid longer word (e.g. SIDE → ASIDE, SNIDE, SLIDE).
  Classic (2min): find all valid insertions;
    each = 10 pts, middle insertion = 15 pts, complete all = +25 bonus
  Survival: 8s per seed word; any correct insertion resets clock
Seeds with ≥4 solutions including ≥1 middle insertion.
APIs: puzzle (seed), validate (stretched + seedWord), solutions (seed).

SUGGESTIONS / NICE-TO-HAVES FOR GAMES:
- In-game tutorial/walkthrough for first play (especially Shell Words,
  Word Bloom, Word Stretch which have complex mechanics)
- Replay mode: after finishing, show all valid answers the player missed
- Word Ladder: show the optimal path after finishing
- Word Sweep: show a heat map of found vs missed words on the grid
- Ladder Rush: ghost timer showing the player's previous best pace
- Shell Words / Deep Shell Words: hint that reveals the boundary letters
- Word Bloom: show the full possible chain tree after the round ends
- Cross-game combo bonuses (e.g. play 5 different games in one day)


========================================================================
2. AUTHENTICATION
========================================================================

The platform supports optional accounts — all games are playable as a
guest. Signed-in users get persistent stats, leaderboard presence,
friends, challenges, groups, and achievements.

Sign-up methods:
  1. Email + password (bcryptjs hashing, email verification required)
  2. Google OAuth (passport-google-oauth20)

Flows:
- Registration: email + name + password → verification email sent via
  Resend → user must verify before full access
- Login: email/password or Google OAuth
- Forgot password: email sent with time-limited reset token
- Email verification: token-based, re-send option available
- Session persistence: express-session with in-memory store (dev) or
  express-mysql-session (production with MySQL)

Auth modal: a single modal handles sign-in, sign-up, forgot password,
and reset password flows with animated transitions between views.

SUGGESTIONS / NICE-TO-HAVES:
- Apple Sign-In (important for iOS users if a mobile app is ever added)
- Magic link / passwordless login option
- Two-factor authentication for accounts with social/leaderboard data
- Account deletion with full data wipe (GDPR compliance)
- Username/display name separate from email (currently uses full name)
- Avatar upload (currently only Google OAuth profile picture is used)

========================================================================
4. STATS SYSTEM
========================================================================

Hybrid stats: guests use localStorage; signed-in users sync to backend.

Tracked per game, per user:
- Best score (all-time)
- Games played
- Games won
- Words found (cumulative)
- Last played timestamp

Stats are submitted to the server after each game via a POST to
/api/stats. The server upserts into the user_game_stats table.

On the Stats page (/stats), users see an overview of their performance
across all games they've played, sorted by games played or best score.

SUGGESTIONS / NICE-TO-HAVES:
- Score trend chart over time (line graph per game)
- Session count vs words found ratio (words per session efficiency)
- "Your best day" highlight (highest total score in a single day)
- Percentile ranking: "You scored better than 78% of players today"
- Stats comparison: compare your stats with a friend side-by-side
- Export stats as CSV or PDF for personal records
- Weekly/monthly recap email ("Here's how you did this week")
- Heatmap calendar (like GitHub contributions) showing play frequency
- Improvement tracking: "Your Word Ladder average improved 15% this month"


========================================================================
5. STREAK SYSTEM
========================================================================

A daily streak tracks consecutive days a signed-in user has played at
least one game. Stored in the user_streaks table:
- currentStreak: days in a row
- longestStreak: all-time personal best
- lastPlayedDate: used to determine if today's play extends the streak

The streak is displayed on the Stats page and incrementally updated
when the user submits game results.

SUGGESTIONS / NICE-TO-HAVES:
- Streak shield (paid feature): protect against one missed day per month
- Streak leaderboard: who has the longest current streak globally
- Streak recovery: if you miss a day, a grace period (e.g. 2-hour window
  after midnight) before the streak resets
- "Streak at risk" push notification (if notifications are ever added)
- Visual streak flame on the user's profile and leaderboard entry
- Friends streak comparison: "Alice has a 14-day streak, you have 9"


========================================================================
6. ACHIEVEMENTS
========================================================================

19 achievement definitions are currently implemented. Achievements are
unlocked based on cumulative play behaviour and stored in the
user_achievements table (userId, achievementId, unlockedAt).

Achievements are checked server-side after game stats are submitted.
Earned achievements show on the Achievements page (/achievements) and
on the user's public profile.

Each achievement has: ID, name, description, icon (emoji or Lucide icon),
and the unlock condition.

SUGGESTIONS / NICE-TO-HAVES:
- Tiered achievements: Bronze / Silver / Gold versions of the same goal
  (e.g. Play 10 games → 50 games → 200 games)
- Secret achievements: hidden until unlocked (adds discovery excitement)
- Achievement points total: a score representing overall platform mastery
- Shareable achievement cards ("I just unlocked X on xtraWordinary!")
- Game-specific achievement sets (e.g. Shell Words-specific badges)
- Seasonal achievements (e.g. "Played on New Year's Day 2026")
- More achievement definitions (currently 19 — could grow to 50+)


========================================================================
7. GLOBAL LEADERBOARD
========================================================================

The leaderboard (/leaderboard) shows top scores per game, globally.
Each entry stores: userId, gameSlug, score, playerName, playedAt.

Users can filter the leaderboard by game slug using a dropdown or tabs.
Word Sweep has two separate tabs (Classic and Guided/Word Unpack).

Scores are submitted server-side after each game. The leaderboard
shows the all-time top N scores per game. Player names link to profiles.

Signed-in users appear on the leaderboard. Guest scores are not stored.

MySQL storage uses optimised SQL aggregations for leaderboard queries
rather than loading all entries into memory.

SUGGESTIONS / NICE-TO-HAVES:
- Leaderboard notifications: "You've been overtaken by Alice in Word Ladder"
- Score verification: flag suspicious outlier scores for admin review
- Regional leaderboards (by country, if location data is ever collected)
- Per-difficulty leaderboard where games have difficulty variants
- Pro badge shown next to paid subscribers' names on the leaderboard
- Animated entry when a new personal best bumps the player up the board


========================================================================
8. FRIENDS SYSTEM
========================================================================

Signed-in users can search for other users by name and send friend
requests. Friendship is mutual (both must accept). Stored in the
friendships table with status: pending / accepted / declined.

Friends page (/friends) has three tabs:
  Friends: list of accepted friends with avatar, name, profile link,
    Challenge button, and Remove button
  Requests: incoming pending requests with Accept / Decline actions
  Challenges: all sent and received challenges (see section 9)

User search is debounced (350ms) with a live results dropdown.
Users can be removed as friends at any time.

Friends list is used in:
- Friend challenges (select a friend to challenge)
- Challenge game detail page (look up friend avatar for banner)
- Navigation unread count (challenges from friends)

SUGGESTIONS / NICE-TO-HAVES:
- Mutual friends display: "3 mutual friends" on search results
- Friend suggestions: recommend users with similar game tastes
- Online indicator (last active within X minutes — privacy-toggle)
- Block / report user (separate from unfriend)
- Friend request message: optional note when sending a request
- "Friends who play this game" shown on game detail pages
- Notification when a friend earns a new achievement
- Friends sorted by: recent activity, most challenges played


========================================================================
9. FRIEND CHALLENGES
========================================================================

Signed-in users can challenge friends to any of the 18 seeded games.
The full flow:

1. Challenger picks a friend and game (from game-detail or friends page)
2. A random seed is generated; challenger is navigated to the game with
   ?challenge-new=friendId&seed=N in the URL
3. Challenger plays the seeded game; score is automatically captured
   via the wordplay-game-result custom event
4. On game completion, a POST to /api/challenges creates the challenge
   record with: senderId, receiverId, gameSlug, senderScore, seed, message
5. Receiver sees a notification dot in the nav and a "Play" button on
   their Challenges tab
6. Receiver navigates to the same game with ?challenge=id; the same seed
   is used so both players play the identical puzzle
7. Receiver's score is auto-submitted via POST /api/challenges/:id/complete
8. The result card shows: winner/loser/tie, both scores, opponent avatar
9. Sender gets a notification dot when the result is ready; visiting the
   Challenges tab auto-marks results as viewed

Challenge cards on the Friends page show:
- Game name, status (Pending / NEW / Won / Lost / Tied)
- Opponent avatar + name
- Both scores (when completed)
- Optional message from challenger
- "Shared puzzle" indicator when seed is set
- Play button for pending received challenges

Challenge banners inside the game show opponent avatar + name for both
sender mode ("Challenging Alice") and receiver mode ("Challenged by Bob").

The 18 seeded games eligible for challenges are defined in
SEEDED_GAME_SLUGS in shared/schema.ts (single source of truth).

SUGGESTIONS / NICE-TO-HAVES:
- Challenge expiry: auto-cancel pending challenges after N days (e.g. 7)
- Challenge history page (beyond the current flat list on Friends tab)
- "Best of 3" or multi-round challenge mode
- Challenge leaderboard: who has the best win record against whom
- Challenge comment: allow a reply message when accepting/completing
- Push notification when a friend completes your challenge
- Challenge streak: consecutive wins vs the same opponent
- Spectator mode: friends can watch a replay of the seeded game after
  both players have completed it


========================================================================
10. GROUPS & COMMUNITY
========================================================================

Groups let signed-in users create or join private communities. Each group
has an auto-generated invite code for sharing.

Group roles: owner / admin / member.

Group features:
- Admins can start "rounds": a specific game + seed so all members play
  the identical puzzle
- Members submit scores after playing; a per-group leaderboard aggregates
  all-time scores for that group
- Group detail page (/groups/:id) has three tabs: Rounds, Leaderboard,
  Members
- Group round play page (/groups/:id/rounds/:roundId/play) handles score
  auto-submission on game completion
- Groups page (/groups) shows all groups the user is in, with create and
  join-by-code actions
- Group link appears in the authenticated user dropdown menu

DB tables: groups, group_members, group_rounds, group_round_scores,
group_round_attempts (tracks who has started a round), group_activity
(activity feed), group_score_reactions (emoji reactions on scores).

closesAt field exists on group_rounds. Admins can set a closing time when
creating a round; the deadline date is shown on past round cards.

SUGGESTIONS / NICE-TO-HAVES:
- Round announcement: admin posts a message when starting a round
  (already partially in group_activity)
- Pinned announcement on group page for important news (column exists)
- Group discovery: a public groups browse page for featured/public groups
- Group tags: categorize groups (school, family, competitive, casual)
- Per-member stats within a group: rounds played, average score, rank
- Group chat / comment thread per round
- Group rounds history: archive of past rounds with full results
- Admin tools: kick a member, transfer ownership, promote/demote admins
- Maximum member limit per group (free vs paid tier gating)
- Group profile picture / avatar
- Weekly group digest email: recap of the week's rounds and top scores


========================================================================
11. DAILY CHALLENGE
========================================================================

A single daily challenge is available to all users (guest and signed-in)
at /daily. The challenge is the same for every player on a given day.

The challenge picks a game and seed deterministically based on the
current date. Seed parity determines mode for dual-mode games
(e.g. Word Sweep: even seed → Classic, odd → Guided).

The daily challenge is always free — it is the core retention loop and
is never gated behind a paywall.

Guest players can complete the daily challenge; their result is not
stored server-side but is tracked in localStorage to prevent replaying.

SUGGESTIONS / NICE-TO-HAVES:
- Daily challenge streak separate from the general play streak
  (currently the same — could be a distinct "daily dedication" streak)
- Optional difficulty toggle for the daily challenge (same game,
  different seed difficulty tier)
- Historical archive: play any previous day's challenge
- Teacher-assigned daily: a teacher can override the daily game for
  their classroom group (future classroom/school feature)


========================================================================
12. COMMENT SYSTEM
========================================================================

A polymorphic comment system allows signed-in users to comment on:
  - Games (on the game-detail page)
  - Group rounds (on the group round play page)

Comment features:
- One-level threading: replies to top-level comments
- 500 character plain text limit
- Soft delete: content is cleared but comment node preserved for thread
  integrity (shows as "[deleted]")
- Report system: users can report a comment with a reason text
- Read access is public; write/delete/report requires authentication
- Likes on individual comments (see section 13)

Admin dashboard has a "Comments" tab showing reported comments with
a delete action for moderation.

REST routes:
  GET/POST /api/comments
  DELETE /api/comments/:id
  POST /api/comments/:id/report
  GET /api/admin/comment-reports
  DELETE /api/admin/comments/:id

SUGGESTIONS / NICE-TO-HAVES:
- Rich text: basic markdown (bold, italic) or emoji picker
- Comment search within a game's discussion
- Pinned comment: game creator or admin can pin an important comment
- Mention (@username) with notification to the mentioned user
- Pagination or infinite scroll for games with many comments
- Nested replies beyond one level (careful — can get complex)
- Comment count shown on game card on the homepage
- Spam filtering: rate limit comments per user per hour


========================================================================
13. LIKES SYSTEM
========================================================================

A polymorphic likes system allows signed-in users to like:
  - Games (like button on game-detail page)
  - Individual comments (inline heart on each comment)

Guests who try to like are prompted to sign in.

Like counts are stored in the likes table:
  (userId, targetType, targetId) with a unique index — one like per
  user per target.

POST /api/likes toggles the like (like/unlike) and returns
  { liked: boolean, count: number }.

GET /api/likes?targetType=&targetIds= returns counts and
  likedByMe booleans for multiple targets in one request.

The LikeButton component handles optimistic updates and renders in two
sizes: default (game detail page) and small (inline on comments).

SUGGESTIONS / NICE-TO-HAVES:
- Like count shown on game cards on the homepage (social proof)
- "Most liked" sort option on the game library homepage
- Notification when your comment gets a like
- Reaction variety: expand beyond ❤️ to 👍 🔥 😂 😮 (optional complexity)
- Like history page: see everything you've liked
- Like milestones: "Your comment reached 10 likes!" achievement

15. NAVIGATION & NOTIFICATIONS
========================================================================

A sticky top navigation bar is present on all pages. It contains:
- Logo/home link (left)
- Nav links: Home, Daily, Ranks, Stats, Badges (icons + labels)
- Sound toggle (mute/unmute sound effects)
- Theme toggle (light/dark mode)
- User menu (right): avatar/name, dropdown with profile, friends,
  groups, admin (if admin), sign out
- Sign In button (if not authenticated)

Notification dot system:
- A red dot appears on the user menu button when:
    1. A friend has challenged you and you haven't played (pendingCount)
    2. A challenge result is ready to view (resultCount)
- The Friends dropdown item shows a matching dot
- Clicking the user menu with a dot navigates Friends → Challenges tab
- The dot clears once challenges are played / results viewed
- Query refetches every 60 seconds to stay current

SUGGESTIONS / NICE-TO-HAVES:

16. UI / UX & PLATFORM
========================================================================

Tech stack: React 18, TypeScript, Wouter (routing), TanStack React Query
(data fetching/caching), Tailwind CSS, Shadcn/ui components, Framer Motion
animations, Lucide React icons.

Themes:
- Light and dark mode, toggled via the nav bar button
- Theme preference saved to localStorage and applied on load
- CSS variables drive the colour system; Tailwind utility classes
  reference those variables

Sound:
- Optional sound effects during gameplay (correct/incorrect feedback)
- Sound toggle in the nav bar; preference saved to localStorage

Animations:
- Page transitions (opacity + Y slide) via Framer Motion AnimatePresence
- Game component entrance animations
- Score displays with animated number reveals
- Spring animations on game icons

Responsive design:
- Works on mobile, tablet, and desktop
- Nav labels hide on small screens (icon-only); labels reappear sm:inline
- Game layouts adapt to screen width

Loading states:
- Skeleton loaders on game detail, profile, and leaderboard pages
- Spinner indicators for mutations (challenge submission, etc.)

Error states:
- "Game not found" fallback on game-detail
- "Challenge not found" error card with back navigation
- Toast notifications for success and error states throughout

SEO:
- Each page has a unique title tag and meta description
- Open Graph tags for social sharing

Data layer:
- IStorage interface with MemStorage (dev/fallback) and MySQLStorage
  (production). MySQLStorage fully implements all methods.
- Drizzle ORM with mysql2 driver; schema in server/db-schema.ts
- DB indexes on all frequently queried columns
- express-mysql-session for persistent sessions in production

SUGGESTIONS / NICE-TO-HAVES:
- PWA service worker: add offline caching so the daily challenge works
  without internet (manifest.json is already in place)
- Keyboard accessibility audit: ensure all interactive elements are
  reachable and operable via keyboard
- Screen reader / ARIA audit: particularly for game grids and timers
- Reduced motion: respect prefers-reduced-motion for users sensitive
  to animation
- Font size / zoom preference: accessibility setting in user profile
- Page load performance: lazy-load game components (code splitting)
  so the initial bundle isn't massive
- Error boundary components to prevent a single game crash from
  taking down the whole page
- Comprehensive end-to-end test coverage (Playwright)
- Onboarding flow for new users: a guided tour of the homepage,
  daily challenge, and first game
- Cookie consent banner (required for GDPR if analytics/ads are added)
