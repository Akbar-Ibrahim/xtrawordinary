GROUP VS GROUP CHALLENGES
────────────────────────────────────────────────────────────

1. Huddle Mode (Phase 1)
   Two groups challenge each other to a synchronous game session.
   One designated typist per group; the rest shout answers. Both groups
   start at the same time via the existing mutual-Ready + countdown flow.
   Same puzzle/seed given to both sides. Works for ALL duel games.
   Entry point: "Challenge Another Group" on the Group detail page.
   No new game logic needed — same engine as 1v1 duels.

   OPEN DESIGN QUESTION — Typist selection:
   Currently the typist is determined by admin role: the admin who sends
   the challenge plays for their group; whichever admin accepts first plays
   for the other group. Alternatives to consider:
     a) Challenger nominates any group member (not just admin) when creating
        the challenge — adds a member-picker step to the challenge dialog.
     b) "Claim the seat" lobby — any member can join the duel room before
        it starts and the first to click Ready becomes the typist; others
        are auto-moved to spectator. More spontaneous, less predictable.
     c) Group vote — members vote on who should represent them; majority
        wins. More democratic but adds latency before the game can start.
   Current behaviour (admin-only, first-accept-wins) ships as Phase 1.
   Revisit before Team Race Mode (Phase 2) since that feature makes
   typist selection irrelevant (everyone plays).

2. Team Race Mode (Phase 2)
   Every group member joins on their own device. Members play
   simultaneously; answers are pooled and de-duplicated for the team.
   Real-time team score feed shows both groups' aggregate tallies live.
   Works for simultaneous race games: Anagram Solver, No Repeats, Word
   Stack, Letter Pool, Word Maker, Word Split, Word Scramble.
   Design questions to resolve: player cap, score normalisation for
   unequal group sizes, quorum (min members needed to start).

3. Relay Mode (Phase 3)
   Teams rotate which member is the active typist each round — each
   member gets a turn. Works for turn-based games.
   Build after Huddle and Team Race are stable.

WORD WARS — RECURRING COMPETITIVE EVENTS
────────────────────────────────────────────────────────────

4. Solo Wars (individual bracket tournament)
   A recurring bracket-style tournament open to all players.
   Players sign up during a registration window; the bracket is seeded
   by ELO rating. Each round is a best-of-3 series (different game types
   per round, chosen by the platform). Players have a 24-hour window to
   complete each battle. Losers are eliminated; the winner of the final
   earns a permanent "Word Wars Champion — Week N" badge on their profile.
   A hall of fame page records all past champions. Reuses the existing
   duel engine, ELO system, and badge/achievement infrastructure.

5. Guild Wars (group bracket tournament)
   Guild Wars is to Huddle what Solo Wars is to Duels — the same group-vs-group
   mechanic scaled up into a full bracket tournament.

   The analogy:
     Individual 1v1    →  Duel
     Individual bracket →  Solo Wars
     Group 1v1         →  Huddle
     Group bracket     →  Guild Wars

   How it works:
   - Groups register as a unit (not individual members).
   - The bracket is seeded by a group ranking (group ELO, or registration order
     for v1). Padded to next power-of-2 with BYE slots, same as Solo Wars.
   - Each match = a Huddle battle between two groups. One typist represents
     each group (the admin who created/accepted the challenge), using the
     existing Huddle/duel room engine unchanged.
   - The winning group advances; the losing group is eliminated. Groups win
     as one and lose as one — no individual scoring, no score pooling.
   - The last group standing wins the Guild War. All members of the winning
     group share the champion recognition (badge on group page + notification
     to all members).
   - Edge case: if a group reaches a round where their only remaining opponent
     is themselves (impossible in a bracket — but if a group somehow fields
     both sides), the bracket resolves naturally since only one side can advance.

   What's new to build (on top of Solo Wars + Huddle):
   - guild_wars_tournaments table (mirrors word_wars_tournaments but keyed on groups)
   - guild_wars_registrations table (groupId, tournamentId)
   - Bracket draw that seeds groups instead of individuals
   - Each match triggers a Huddle challenge between the two groups
   - finalizeGame hook calls resolveGuildWarsMatch (mirrors resolveWordWarsGame)
   - Group champion record + notification to all winning group members
   - Frontend: Guild Wars lobby, bracket page (groups as nodes), group champion badge

   Both Solo Wars and Guild Wars live under the same "Word Wars" nav entry.
   Shared components: registration/scheduling layer, bracket UI, Hall of Fame.

   NOTE — Dramatic challenge notifications:
   When a Word Wars bracket is drawn and opponents are matched, each player
   receives a flavourful, war-themed notification (e.g. "Your opponent has
   been chosen. The war begins. Prepare yourself."). Similarly, when a Guild
   War is declared, all members of the challenged group receive a dramatic
   call-to-arms notification. This uses the existing notification system;
   only the copy and a new notification type (word_war_matched / guild_war_declared)
   need to be added. Consider applying the same treatment to standard Duels —
   replacing the plain "X challenged you" notification with something like
   "X has drawn their sword. Will you accept the challenge?" for no extra
   engineering cost. (Optional — to be decided at build time.)

WORD WARS — POST-LAUNCH IMPROVEMENTS

6. Show Word Wars on the home page
   Add a Word Wars promo card to the home page alongside the existing Duels
   card. If a tournament is currently in registration, show how many warriors
   have signed up and the deadline. Card links to /word-wars.
   File: client/src/pages/home.tsx

7. Auto-forfeit inactive players when a round deadline passes
   roundDeadlineHours exists in the data model but is never enforced. Add a
   scheduled check (triggered on tournament-related API reads) that compares
   match creation time + roundDeadlineHours against the current time. If a
   match is still pending/active after the deadline, forfeit the player who
   hasn't completed their games; advance the bracket automatically; notify
   both players.
   Files: server/word-wars-engine.ts (checkAndForfeitExpiredMatches),
          server/routes.ts, server/storage.ts + mem/mysql implementations.

8. Word Wars stats section on player profiles
   Show a "Word Wars" section on profile pages: tournaments entered, matches
   won/lost, and titles won (tournament name + date, linking to bracket).
   May need a GET /api/users/:id/word-wars-stats endpoint that aggregates
   match outcomes by userId across all tournaments.
   Files: client/src/pages/profile.tsx, server/routes.ts,
          server/storage.ts + mem/mysql implementations.
